## Persistence, secrets and Scribe

`host.secretGet` stamps `sandbox.plugin_id`; `service/plugin_host.rs:512` uses that plugin's bucket. `codeterm-util/src/secret_file.rs:178` constructs service `codeterm.plugin.{plugin_id}`. Thus the full pair belongs under `higgsfield-api-key` in Higgsfield's host bucket. A global vault item with the same name does not prove this bucket is provisioned. No real secret metadata/value was inspected or provisioned in this spike.

Plugin data files/sqlite are available under sandbox confinement (SDK host filesystem/sqlite methods). A studio must persist a bounded versioned ledger partitioned by **trusted** owner scope, sanitize errors/URLs, reconstruct on reopening, and never persist media frame tokens as durable job IDs or budget authority. Current source does not establish trusted owner stamping for `ct.invoke`; local argument partitioning alone is insufficient.

The same ownership issue applies before a media handle is minted: Courier's backend callback is `mediaFile(id)`, without a trusted surface-owner/run context parameter. Frame ownership confines the resulting delivery token, but does not by itself authorize which owner's result the supplied `id` may resolve. Unpredictable IDs and plugin-local files are not cross-owner authorization. Concierge/Courier must provide or approve an exact-frame scoped result-lookup binding; Loom separately authorizes durable run handoff. Until that is proved, two-agent media isolation is an explicit blocked dependency.

The existing transcriber plugin at plugin-repo base `5c473f057b8d94f8b63f003f81b42f7831932800` declares `transcriber:true` in `transcriber/plugin.json`. `transcriber/src/plugin.ts` exports `transcribe(path,lang?)` and `transcribeStatus`; local mode ffmpeg→16kHz mono WAV→whisper.cpp, with silence gating/cleanup; configured remote mode uses curl multipart to its configured endpoint. This source read did not execute/install/configure it. Host `codeterm-plugin/src/transcribe.rs` defines `Transcriber` registry and disk-path contract, and `codeterm-bridge/src/chatpipeline/mod.rs:173` chooses the active registry entry. Integration docs auto-register transcriber as audio→text. Scribe should implement that existing selectable capability; no separate transcription UI or hardcoded vendor selection. Ordinary studio-to-selected-transcriber invocation is not established by a method on Host; any such new route needs an explicit generic capability, not an invented SDK method.

Existing saved image rendering is distinct from plugin frame delivery: `packages/chat-core/src/localArtifactDirective.ts` parses standalone `@ds-image ABSOLUTE_PATH`; `packages/chat-ui/src/LocalImageGallery.tsx` consumes host-authorized local artifacts. Authorized saved paths can be shown there. This is not proof a Blueprint agent can review media or an opaque iframe can fetch arbitrary local paths.
