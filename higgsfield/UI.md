`src/ui.ts` supplies document-only `ui.snapshot({offset?,limit?})`, `ui.details({id})` and `ui.schema({operation})`. All resolve current access through the same CommandPorts resolver and same service history/catalog. A host-registered document/frame/surface is required; object-shaped forged context is not authority. UI arguments are at most 4,096 serialized UTF-8 bytes. Snapshot pages default to 20, accept 1–50 items and offset 0–10,000, with a 256 KiB total serialized UTF-8 response cap. Total details are at most 64 KiB; total schema responses are at most 128 KiB. Schema traversal is bounded to depth 12 (root at depth 0; edges to child schemas, including references, count) and 128 declared properties across the projection. Unsupported, recursive or oversized schemas/details return a typed unavailable result with no partial reusable request; schemas retain their actual catalog fields and constraints. Unknown argument keys and unowned IDs refuse. Public agent verbs and summaries are unchanged. Private prompts/settings go only to the authorized document; activity excludes them. Scope/binding/authRevision/approval, transport URLs, raw errors and host file paths do not enter DTOs.

Trusted proof/admission must supply its own current authority; merely showing a button grants none. Provider/service cost and noReplay algorithms are unchanged. ## DTO and private response correction

The correction restores the original exact DTO bounds above, rather than accepting the first candidate's 16,000-character arguments/24-default/48-max pages/128-KiB-params assumptions. Every response cap counts the whole JSON envelope in UTF-8, including non-ASCII strings, escapes and schema metadata. Bounds never increase automatically and reusable params/schema are not truncated. Authorization refusal remains separate from a typed unavailable projection. UI transport types and controller explicitly handle unavailable results.

Refresh clears inspector details before awaiting visibility and fences prior detail/schema reads. Request revisions discard out-of-order snapshots, inspections and model selections after Back, invalidation, a newer request, reuse or disposal. Presence of the same ID in a later snapshot never authorizes retaining an old details object. These are UI cancellation fences, not a replacement backend authorization model.

Watt adopted Iris's precise placement rule: the prompt is prominent, followed by required fields without schema-valid defaults, then only adapter-marked key fields up to three parameters. If more than three required-without-valid-default inputs exist, all stay visible and no optional inputs join them. No key hints or defaults are invented. Required fields have screen-reader text and aria-required. Remaining optional/defaulted settings show a changed count and free Reset; only defaults accepted by the existing vendor schema validator are restored, through the existing edit/quote invalidation path.

Structured editors synchronize external values while preserving a user's unfinished text, and free reuse/model selection increment the actual React form key to remount prior drafts. Node regressions cover the controller's selection revision and actual server-rendered replacement textarea; mounted DOM event and focus proof still belongs to the parent Browser gate.
