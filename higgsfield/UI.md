## DTO and private response correction

The correction restores the original exact DTO bounds above, rather than accepting the first candidate's 16,000-character arguments/24-default/48-max pages/128-KiB-params assumptions. Authorization refusal remains separate from a typed unavailable projection. UI transport types and controller explicitly handle unavailable results.

Refresh clears inspector details and the prior snapshot before awaiting visibility and fences prior detail/schema reads. Independent request generations discard out-of-order replies. Back/reuse/model selection cancel obsolete inspection/selection replies without canceling a required visibility refresh; a known context replacement atomically clears snapshot, draft/settings/note, details and quote identity, advances the context epoch, and fences every earlier response. The actual dev owner handler performs that reset before setOwner/invalidation and immediate model selection. Presence of the same ID in a later snapshot never authorizes retaining an old details object. These are UI cancellation fences, not a replacement backend authorization model.
